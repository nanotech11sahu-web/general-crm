# PMC Demo — CRM/Business Platform

Build follows `PMC_CRM_BUILD_PROMPT.md` (13 phases, Phase 0–12). **All 13 phases are now implemented**: **Phase 0 — Foundation**, **Phase 1 — Core CRM: Contacts & Lead Management**, **Phase 2 — Lead Generation Suite I: Sites, Forms, Chat Widget**, **Phase 3 — Lead Generation Suite II: Ecom, Ad Launcher, AI Social, Vibe Prospecting, URLs**, **Phase 4 — Lead Automation: Email Marketing, WABA, Workflow Automation, Bulk Campaigns**, **Phase 5 — Sales, Calendar & Booking: Sales Performance, Webinars, IVR Calling, Proposal Builder, Calendar, Event Type Builder**, **Phase 6 — Finance: Dashboard, Billing, Products, Payment Gateway, Tax Profiles**, **Phase 7 — AI Suite: AI Brain, AI Agents, Dashboard, LLM-gateway abstraction**, **Phase 8 — Operations: Projects, HRM, Education/School**, **Phase 9 — Community & LMS, Inbox**, **Phase 10 — Settings, RBAC Depth, White-Label & App Store**, **Phase 11 — Cross-Module Polish, Agency Layer & Mobile App Shell**, and **Phase 12 — Hardening, Full Regression Testing & Launch Readiness**. See `docs/ARCHITECTURE.md`, `docs/ADMIN_GUIDE.md`, `docs/openapi.yaml`, and `docs/LAUNCH_CHECKLIST.md` for the documentation this final phase produced.

## Structure

- `backend/` — Express + TypeScript + Mongoose API (JWT auth, RBAC engine, shared services)
- `frontend/` — React + TypeScript + Vite + Tailwind (global app shell, design system primitives)

## What's implemented (Phase 0)

- Multi-tenant data model: `Workspace`, `User`, `Membership`, `Role`, `LeadershipTitle` — every collection scoped by `workspaceId`
- JWT access + refresh auth (signup, login, refresh, logout, `/me`)
- Generic RBAC engine: 14 modules × 4 actions (read/create/edit/delete), system "Owner" role always has full access, custom roles + additive Leadership Title overrides, enforced via `requirePermission()` middleware
- Shared services scaffolded for reuse by every later phase: `DeletedItem` (30-day recover bin), `Tag` (seeded Hot/Warm/Cold), `CustomField` (6 field types), `OnboardingTask` (30-item "Finish your setup" checklist), `Notification`, and an in-process event bus for future workflow triggers
- Frontend design system tokens (light/dark via CSS variables) + primitives: Button, Input, Card, Badge, Modal, Skeleton, EmptyState, Toaster (Framer Motion)
- Global app shell: collapsible sidebar (13 modules + data-driven External Links), top bar (workspace switcher, notification/announcement icons, profile menu), mobile bottom nav + drawer, floating AI assistant button, floating Report tab
- `usePermission()` hook for gating UI by RBAC

## What's implemented (Phase 7)

- **LLM-gateway abstraction (the centerpiece of this phase) — `callGateway()`:** a single choke point every AI feature in the app routes through — deterministic template-based content generation, in-memory response caching (5-min TTL), token/cost/latency estimation, per-call logging to `AiRequestLog` for the Dashboard, wallet debiting (`ai_gateway_usage`, reusing Phase 3's ledger) for the default internal provider, and a BYOK bypass (no debit) when a workspace has a connected provider — every earlier phase's "stub the AI call" point (see below) now calls this gateway for real
- **AI Brain (Phase 7 core DoD):** one read-only knowledge pack per module (18 total) — 9 modules with an existing backend (Calendar, Prospecting, Workflows, WhatsApp, Email Marketing, Finance, Ad Launcher, Forms, Chat Widget) are auto-seeded from that module's real queried workspace data, not static text; the remaining 9 (modules not yet built) get an explicit "ships in a later phase" placeholder. Chat with Brain does naive keyword-overlap matching against seeded + manually-added docs, falling back to the seeded summary when nothing matches (never a true "no answer," since a seed always exists) and logging genuine misses to an Unanswered Questions tracker with a Resolve action. Verified live end-to-end: the Finance pack answered "What is our current MRR?" grounded in a real ₹7,500/month subscription created moments earlier
- **AI Agents (Phase 7 core DoD):** a Templates gallery with 4 install-in-one-click starter agents (Marketing/Sales/Operations/Finance) — Marketing is fully spec'd (Tone, System Instructions, Guardrails: never auto-publish, never make a false/unverifiable claim, never reproduce competitor content; Included Skills: Generate Marketing Copy, Tag and Segment Lead) as the template for the other 3. Every agent reply structurally appends "This is a draft for your review — nothing has been sent or published," so the no-auto-publish guardrail is enforced by code, not just prompt text. Verified live: installing the Marketing Agent and invoking it produced a properly tone/skill-framed draft headline
- **Dashboard:** token usage/active agents/requests/response time/success rate/cost/conversations/cache-hit-rate KPIs, a 7/30/90-day token usage chart, model/provider breakdown, and an "Advisory Board AI" entry point stubbed as a later-phase placeholder — all computed from real `AiRequestLog` aggregation, not mock data
- **4 stub-AI-call retrofits, each verified with an integration test asserting a real `AiRequestLog` entry:** Contact Lead Scoring's AI Next Best Action (Phase 1), Ecom's AI Store Builder (Phase 3), Forms' AI Builder (Phase 2/3), Email Marketing's Compose-with-AI (Phase 4)
- **BYOK provider connections:** connect-state stub (same pattern as Zoom/Razorpay) for Gemini/OpenAI/Claude/DeepSeek — masks and stores a "connected" flag and skips the wallet debit on gateway calls, but never makes a real outbound call to the vendor
- A real bug was caught and fixed during live verification: `ensureSeeded` only created a pack's seeded doc once and never refreshed it, so the Finance brain pack kept answering from a frozen ₹0 MRR snapshot even after a real subscription was created — fixed by upserting the seeded doc's content on every read, with a regression test asserting it reflects newly-created data
